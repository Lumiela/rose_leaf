# v3_twostage: 2단계 구조 타당성 검증

구상: [1단계] 잎이 있는 영역 찾기 → [2단계] 그 영역을 잘라 모델로 이상 상태 분리.
재학습 없이 두 가지를 검증했습니다(2026-10-13).

```
v3_twostage/
├── scripts/
│   ├── stage1.py                  # 1단계 후보: 색 기준 잎 마스크(HSV), 마스크 다듬기, 식물 영역 박스
│   ├── exp1_hsv_leaf_recall.py    # 검증 1: 색 기준이 잎(클래스별)을 얼마나 잡는가
│   ├── exp1b_missed_leaf_colors.py# 검증 1b: 놓친 잎의 색 분석
│   └── exp2_roi_crop_predict.py   # 검증 2: 원본 해상도 타일 예측 (ft_from_v1 사용)
├── results/
│   ├── exp1_hsv_leaf_recall/      # summary.json, worst4_random4_by_class.jpg, missed_leaves_original_colors.jpg
│   └── exp2_roi_crop/             # 사진별 비교 시트(*_all.jpg, *_disease.jpg), summary.json
└── logs/                          # exp1.log, exp1b.log, exp2.log
```
실행: `python v3_twostage/scripts/<스크립트>.py > v3_twostage/logs/<이름>.log 2>&1` (model/에서)

## 검증 1: 색 기준 1단계의 잎 인식률 (Dataset 누끼 잎, 실제 잎 크기 160px로 축소)
| 클래스 | 표본 | 평균 인식률 | 중앙값 | 80% 미만 잎 | 50% 미만 잎(사실상 놓침) |
|---|---|---|---|---|---|
| Black Spot | 400 | 0.913 | 0.992 | 12.0% | 5.0% |
| Fresh | 400 | 0.861 | 0.999 | 19.2% | 13.5% |
| Hole | 400 | 0.854 | 0.986 | 20.5% | 13.0% |
| Yellow | 42 | 0.943 | 0.978 | 4.8% | 2.4% |
(구멍 메우기 + 확장 적용 기준. 다듬기 전 원본 마스크는 50% 미만 잎이 Black Spot 8.0%, Fresh 16.5%, Hole 17.5%, Yellow 2.4%)

놓친 잎의 원인(검증 1b):
- **채도 낮음 (S 10~30):** 회색이나 바랜 잎. Black Spot에서 놓친 잎의 대부분이 이 경우입니다.
- **색상 범위 밖:** 붉거나 보라색인 새 잎(H 148~175, Fresh), 갈색이나 붉게 마른 병든 잎(H 8~15, Hole).
- **결론:** 색 기준만으로는 정작 찾아야 할 갈색·마른 병든 잎을 통째로 놓칩니다. 색 기준을 1단계의 유일한 판단 기준으로 쓰면 안 됩니다.

## 검증 2: 원본 해상도 타일 예측 (2단계 = ft_from_v1, 재학습 없음, 신뢰도 0.25)
| 사진 | 방식 | 검출 | Fresh | Hole | Black | Yellow |
|---|---|---|---|---|---|---|
| 1 (멀리서) | 기존: 전체를 640으로 축소 (0.32배) | 116 | 50 | 64 | 1 | 1 |
| 1 | 800px 타일 (0.8배) | 160 | 126 | 28 | 4 | 2 |
| 1 | 640px 타일 (1.0배) | 118 | 98 | **17** | 1 | 2 |
| 1 | 800px 타일 + 배경 회색 | 165 | 133 | 27 | 4 | 1 |
| 2 (가까이) | 기존 | 103 | 96 | 7 | 0 | 0 |
| 2 | 800 / 640 / 800+회색 | 50 / 48 / 54 | 43 / 44 / 47 | 4 / 3 / 6 | 1 / 0 / 0 | 2 / 1 / 1 |
| 3 (가까이, 학습에 안 쓴 사진) | 기존 | 105 | 98 | 2 | 3 | 2 |
| 3 | 800 / 640 / 800+회색 | 69 / 59 / 70 | 67 / 56 / 66 | 2 / 3 / 2 | 0 | 0 / 0 / 2 |

- **식물 단위 영역 자르기:** 세 사진 모두 식물이 하나의 영역으로 합쳐져 사진 전체가 됐습니다. 그래서 해상도 이득을 보려고 타일 예측을 추가했습니다(첫 실행 기록은 README 참고).
- **멀리서 찍은 사진 (1):** 타일 예측으로 건강한 잎을 Hole로 판정한 건수가 64건에서 17~28건으로 줄고, Fresh 판정이 50건에서 98~133건으로 늘었습니다. 해상도 가설을 뒷받침합니다.
- **가까이서 찍은 사진 (2, 3):** 결과가 나빠졌습니다. 검출 수가 103건→48~54건, 105건→59~70건으로 줄었고, 타일 경계에 네모 모양의 큰 마스크가 생겼습니다. 잎이 학습 때 크기보다 너무 커졌기 때문입니다.
  - 학습 때 빽빽한 장면의 잎은 640 입력에서 약 30~90px였습니다.
  - 기존 방식에서는 가까이 찍은 사진의 잎이 이미 적정 크기였습니다.
- **배경 회색 채우기:** 재학습 없이는 효과가 없습니다. 첫 실행에서 영역 전체에 회색을 채웠을 때 사진 1이 Hole 64건→68건, Fresh 50건→19건으로 오히려 나빠졌습니다.

## 결론과 다음 단계
1. **1단계:** 색 기준 단독은 부적합합니다. 학습된 잎 1개 클래스 모델과 함께 쓰고, 잘라낼 때는 픽셀 단위가 아니라 영역(박스) 단위로 씁니다.
2. **2단계:** 확대 배율을 사진마다 고정하지 말고, 잎 크기를 추정해 640 입력 기준 약 30~90px이 되도록 조정해야 합니다(배율 자동 조정 + 타일). 타일 경계에 걸린 검출은 버리고, 겹치는 타일 사이의 중복은 합쳐야 합니다.
3. **배경 처리:** 회색 채우기 같은 배경 처리는 2단계 학습 데이터에도 똑같이 적용해서 다시 학습할 때만 의미가 있습니다.
