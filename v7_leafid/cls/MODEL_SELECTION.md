# 2단계 잎 분류 모델 선택: EfficientNetV2-S vs ConvNeXt-Tiny

- 작성일: 2026-10-14
- 관련 작업: 서버 `model/v7_leafid/cls/` (v7 새 구조의 2단계 분류)
- 서버 사본: `model/v7_leafid/cls/MODEL_SELECTION.md`

## 1. 배경
v7 새 구조는 다음 두 단계로 동작합니다.
- **1단계:** 사진에서 잎을 모두 찾아 ID를 붙입니다.
- **2단계:** 잎 ID별 누끼를 분류 모델로 판정합니다. 클래스는 Black Spot, Fresh, Hole, Yellow 4개입니다.

2단계 후보로 YOLO11s-cls, EfficientNetV2-S, ConvNeXt-Tiny, DINOv2 ViT-S/14를 검토했습니다. 비교 학습은 3개로 줄였습니다. 이 문서는 그중 ImageNet으로 사전학습한 CNN을 미세조정하는 방식의 대표로 **EfficientNetV2-S를 넣고 ConvNeXt-Tiny를 이번 비교에서 뺀 이유**를 정리합니다.

## 2. 두 모델의 구조 차이

| 항목 | EfficientNetV2-S | ConvNeXt-Tiny |
|---|---|---|
| 발표 | 2021 (Google, Tan & Le) | 2022 (Meta, Liu et al.) |
| 설계 방향 | 작은 모델로 높은 정확도를 내도록 자동 탐색(NAS)과 균형 확장(compound scaling)으로 설계 | ResNet을 Transformer의 설계 요소로 현대화한 순수 CNN |
| 기본 블록 | 앞쪽은 Fused-MBConv(일반 3×3 합성곱), 뒤쪽은 MBConv(깊이별 합성곱 + SE 채널 주의) | 7×7 깊이별 합성곱 + 역병목(inverted bottleneck) MLP |
| 정규화 / 활성 함수 | BatchNorm / SiLU | LayerNorm / GELU |
| 입력 처리 | 3×3 합성곱 줄기(stem), 점진적으로 해상도 축소 | 4×4 패치 단위로 나누는 줄기(patchify stem) |
| 파라미터 | 21.5M | 28.6M |
| 연산량 | 8.4 GFLOPs (384 입력), 224 입력에서는 약 2.9 GFLOPs | 4.5 GFLOPs (224 입력) |
| ImageNet top-1 (torchvision 가중치) | 84.2% (384 입력 평가) | 82.5% (224 입력 평가) |
| 가중치 파일 | `efficientnet_v2_s-dd5fe13b.pth`, 83MB | `convnext_tiny-983f1562.pth`, 약 109MB |

ImageNet 정확도는 평가할 때의 입력 크기가 서로 다릅니다. 우리 작업은 224 입력으로 하므로, 두 모델의 실제 차이는 표의 수치보다 작을 것으로 봅니다.

## 3. 우리 작업 조건에서의 장단점

| 조건 | EfficientNetV2-S | ConvNeXt-Tiny |
|---|---|---|
| **작고 흐린 입력** (실제 잎 40~150px을 224로 확대) | 작은 해상도에서도 효율이 좋도록 설계됨 | 큰 7×7 필터로 넓은 범위를 보지만, 확대된 흐린 이미지에서의 이점은 불확실 |
| **질감 병변** (반점·구멍) | SE 채널 주의로 특정 패턴에 집중 | 넓은 필터와 깊이별 합성곱으로 질감 표현이 강한 편 |
| **데이터 분포 변화** (합성·원본 → 실제 큐브) | 보통 | 같은 규모 CNN 중에서는 비교적 잘 버티는 편이라는 보고가 많음 |
| **적은 데이터** (원본 2,348장, Yellow 121장) | BatchNorm이라 배치가 작으면 불안정할 수 있음 (이번에는 배치 64라 문제없음) | LayerNorm이라 배치 크기에 덜 민감하고 학습이 안정적 |
| **속도와 장비 배포** (Jetson, TensorRT) | 가볍고 빠름. V100 실측 1.8ms/장 | 연산량이 약 1.5배. TensorRT에서는 LayerNorm·7×7 깊이별 합성곱이 상대적으로 덜 최적화되는 경우가 있음 |
| **구현** | torchvision 내장. 학습 스크립트 완성 | torchvision 내장. 같은 스크립트에서 모델만 바꾸면 됨 |

**정리:** 두 모델의 차이는 일반적으로 정확도 수 %포인트 이내입니다. 장비 배포 쪽은 EfficientNetV2-S가, 데이터 분포 변화와 학습 안정성 쪽은 ConvNeXt-Tiny가 조금 유리합니다.

## 4. 실험 결과 (2026-10-14, `v7_leafid/cls/compare.md`)
- **같은 조건:** 같은 분할(원본 사진 단위, 시드 42)과 같은 렌더링 데이터를 썼습니다. 렌더링 데이터는 선명한 버전과, 긴 변 40~150px로 줄였다 키운 저해상도 버전으로 구성했습니다.
- **두 가지 테스트:** "변형 테스트"는 테스트 원본을 실제 큐브 잎처럼 작고 흐리게 만든 것입니다.
- **실제 잎 판정:** v7 1단계에서 고정 카메라 5장으로 잘라낸 잎 603개에 적용한 판정 분포입니다. 실제 식물은 대부분 건강합니다.

| 모델 | 테스트 정확도 / macro-F1 | 변형 테스트 정확도 / macro-F1 | 변형 테스트 재현율 (반점/건강/구멍/황변) | 추론 ms/장 (V100) | 실제 잎 판정 (반점/건강/구멍/황변) |
|---|---|---|---|---|---|
| **EfficientNetV2-S** | 0.961 / 0.940 | 0.920 / 0.857 | 0.89 / 0.94 / 0.90 / 0.86 | 1.8 | 121 / 249 / 201 / 32 (**이상 판정 59%**) |
| ConvNeXt-Tiny | 이번에 실행하지 않음 | - | - | - | - |
| (참고) DINOv2 ViT-S/14 + 선형 분류기 | 0.920 / 0.854 | 0.903 / 0.832 | 0.89 / 0.93 / 0.84 / 0.86 | 36.5 | 37 / 404 / 115 / 47 (이상 판정 33%) |
| (참고) YOLO11s-cls | 0.942 / 0.873 | 0.931 / 0.829 | 0.93 / 0.98 / 0.84 / 0.57 | 1.0 | 37 / 358 / 171 / 37 (이상 판정 41%) |

- **세 모델이 모두 같은 이상 클래스로 판정한 잎:** 59개입니다(Hole 53, Black 4, Yellow 2).
- **잎 모양과 판정의 관계:** 세 모델이 모두 Hole로 판정한 잎은 볼록도 중앙값이 0.81이었습니다. 절반가량은 0.8 미만으로, 여러 잎이 합쳐졌거나 누끼에 틈이 있는 경우입니다. 반면 세 모델이 모두 Fresh로 판정한 잎은 볼록도 중앙값이 0.99였습니다. 즉 Hole 판정은 실제 구멍보다 **누끼의 모양(틈, 합쳐진 잎)** 에 좌우되고 있습니다.

- **EfficientNetV2-S:** 원본·변형 테스트 모두에서 가장 높습니다. 하지만 실제 잎에서는 건강한 잎의 대부분을 이상으로 판정했습니다.
- **오판 이미지를 확인한 결과:**
  - 1단계 누끼의 잘린 틈이나 잎 사이로 회색 배경이 비치면 Hole로 판정합니다.
  - 여러 잎이 합쳐진 덩어리나 그늘진 잎은 Black Spot으로 판정합니다.
  - 연두색 새잎은 Yellow로 판정합니다.
- **DINOv2:** 테스트 점수는 조금 낮지만, 실제 잎에서 이상 판정이 절반 수준(33%)입니다. 범용 특징이 데이터 분포 변화에 더 잘 버티는 것으로 보입니다.

### 4-1. 입력을 주변 포함 사각형 자르기(bbox)로 바꾼 결과 (2026-10-14, `compare_bbox.md`)
- **변경:** 누끼 대신 잎 긴 변의 1.25배 정사각형을 주변째 잘라 입력합니다. 학습 데이터는 원본 누끼를 실제 큐브 사진 위에 붙여 만들고, 붙이는 잎의 크기를 그 사진의 실제 잎 크기(중앙값 77~104px) × 0.7~1.3으로 맞췄습니다.
- **판정 대상:** 볼록도 0.8 이상이고 화면 가장자리에 닿지 않는 잎 462개입니다. 나머지 141개는 판정을 보류합니다.

| 모델 | 합성 test acc / F1 | 변형 test acc / F1 | 실사 이상 판정 (판정 대상) | 누끼 입력일 때 |
|---|---|---|---|---|
| **EfficientNetV2-S** | 0.920 / 0.859 | 0.873 / 0.825 | **16.2%** (7/387/59/9) | 55.2% |
| YOLO11s-cls | 0.881 / 0.795 | 0.884 / 0.792 | 40.3% | 34.8% |
| DINOv2 ViT-S/14 | 0.801 / 0.666 | 0.760 / 0.641 | 25.8% | 29.0% |

- EfficientNetV2-S는 입력 형태를 바꾸자 실사 오판이 크게 줄었습니다. 2절의 "병목은 모델이 아니라 입력 형태"라는 판단이 맞았습니다.
- 미세조정이 가능한 EfficientNet만 배경이 섞인 작은 입력에 적응했습니다. 특징을 고정하는 DINOv2와 작은 YOLO-cls는 따라오지 못했습니다.
- 남은 이상 판정(Hole 59개 등)은 눈으로 보면 모두 건강한 잎입니다. 잎 사이로 보이는 흰 벽이 Hole로, 밝은 새잎이 Yellow로 판정됩니다. 이는 학습한 Fresh 잎의 색이 실제 큐브 잎과 달라서 생기는 문제로, 실제 건강한 잎을 학습에 넣어 해결할 예정입니다.

### 4-2. 실제 정답 평가와 실제 건강 잎 추가 (2026-10-14, `cls/gt/eval_gt.md`, `cls/gt/eval_real_test.md`)
- **정답 세트:** 고정 카메라 판정 대상 잎 462개에 정답을 달았습니다. 실제 이상 잎은 0개였습니다. 그래서 위 표의 이상 판정 비율은 실제로 모두 오판입니다.
- **bbox_real_aug:** 스마트폰 사진에서 검토한 실제 건강 잎 938개를 Fresh로 넣고, 같은 잎에 합성 이상(구멍·황변·반점)을 그려 이상 클래스로도 넣은 EfficientNetV2-S입니다. 실제 잎만 넣으면 "실제 사진처럼 보이면 건강"이라는 지름길을 학습하는데, 이를 막기 위한 구성입니다.

| 모델 | 고정 카메라 오판율 (A1) | 학습에 안 쓴 사진 오판율 (A4) | 변형 테스트 재현율 Black/Hole/Yellow | 변형 test F1 | 실제 잎 + 합성 이상 감지율 (B4) |
|---|---|---|---|---|---|
| EfficientNetV2-S bbox | 16.2% | 4.0% | 0.787/0.836/0.857 | 0.825 | 0.647 |
| + 실제 건강 잎 (bbox_real) | 0.4% | 0.0% | 0.850/0.791/0.857 | 0.849 | **0.433** (지름길) |
| **+ 실제 잎 위 합성 이상 (bbox_real_aug)** | **0.9%** | **0.5%** | 0.825/0.836/0.857 | **0.862** | 0.980 (학습과 같은 방식이라 낙관적) |

- **현재 2단계 기본 모델:** `runs_bbox_real_aug/effnetv2s/best.pt`
- 실제 이상 잎 검출률은 이상 잎이 생기면 측정합니다.

## 5. 선택과 이유

**결정:** 이번 비교의 CNN 대표로 EfficientNetV2-S를 쓰고, ConvNeXt-Tiny는 이번 비교에서 제외(보류)합니다.

1. **같은 계열 모델끼리의 차이는 작음:** 두 모델 모두 ImageNet으로 사전학습한 CNN을 미세조정하는 방식입니다. 일반적으로 성능 차이가 수 %포인트라, 계열이 다른 YOLO-cls(경량 기준선)와 DINOv2(범용 특징)를 함께 비교하는 편이 더 많은 정보를 줍니다.
2. **실제 성능의 병목이 모델이 아님:** EfficientNet은 변형 테스트에서 0.92인데, 실제 잎에서는 이상 판정이 59%입니다. 이 차이의 원인은 입력 형태입니다. 누끼의 틈이 구멍처럼 보이고, 여러 잎이 합쳐져 잘리고, 새잎의 색이 황변처럼 보입니다. 이 문제는 ConvNeXt로 바꿔도 사라지지 않습니다.
3. **장비 배포:** 최종적으로 Jetson에서 돌릴 가능성을 고려하면, 연산량이 작고 TensorRT 변환이 무난한 EfficientNetV2-S가 유리합니다.
4. **다운로드 최소화:** 이번 비교에 필요한 가중치만 내려받았습니다. ConvNeXt 가중치(약 109MB)는 내려받지 않았습니다.

## 6. ConvNeXt-Tiny를 다시 검토할 조건
- 2단계 입력을 누끼 대신 **배경을 포함한 사각형 자르기**로 바꾸고, 학습 데이터도 같은 형태로 만든 뒤
- 실제 큐브 잎이 학습·평가에 들어가서 **실제 사진 기준 점수**를 잴 수 있게 되면

이때 EfficientNetV2-S, ConvNeXt-Tiny, DINOv2를 같은 조건으로 다시 비교합니다. ConvNeXt 추가에 드는 비용은 가중치 다운로드 109MB와 학습 약 7~8분입니다. 학습 스크립트(`train_effnet.py`)에서 모델 생성 부분만 바꾸면 됩니다.
